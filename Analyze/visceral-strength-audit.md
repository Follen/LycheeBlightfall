# 脏腑之力与自动分支审计（0.3.0）

2026-09-28。代码已接入，离线验证通过；当前没有正在运行的正式服客户端，未验证正式服 M+ / 团本战斗的事件载荷、事件顺序或实际 DPS。没有修改游戏安装目录。

## 固定依据

- SimC：`Analyze/Simc`，commit `4c7c73621e596419b5bd6faa5d68940a9c640379`。
- `ActionPriorityLists/default/deathknight_unholy.simc`：`active_enemies >= 3` 走群怪；吞病位于 cooldowns 优先级，早于普通缠绕/传染。单体 Reaping + Soul Reaper 分支要求收割 debuff 存在且剩余小于 2 GCD；群怪检查突变或仍在生效的饰品增益剩余小于 2 GCD。没有 `visceral_strength` 吞病硬条件。
- `engine/class_modules/sc_death_knight.cpp`：`sudden_doom_execute_effects` 触发脏腑之力；缠绕/传染及其替换技能经 `unholy_rp_execute_effects` 处理。替换传染 graveyard 的动作 ID 为 383269，现已补入，避免爆发期遗漏消耗与突变续时。
- 正式服静态数据 12.1.0.69933 zhCN，PIN `PIN-844e56206c15b8a81da4ca386208008d855bf69b077af8b0cbcbd6adeb14657a`：天赋 434157；邪恶光环 434159 = 5 秒、4% 力量；81340 末日突降 = 10 秒。捕获 `CAP-915f04dd7fc8e144b38f6ccb7dbbd77c93702a60f4ffec1dc16e55debae14252`、`CAP-00f3659f5f262545fa7b19d2a2676c7134e8d2cb42ee7773f23d001386b04579`。表有无关加密分区未覆盖，上述目标记录可读；未叠加服务器 Hotfix。
- UI 源码 commit `09b9db7948abc9b9648dedaab51eb0cf3ee67b31` 与本机 SAT 20260901 的显示/隐藏实现支持监听路径，详见 `sudden-doom-overlay-audit.md`。实现自行监听 SHOW/HIDE 事件，不复制 SAT，不读取它的受限倒计时控件，也不挂钩池化框体 OnShow/OnHide。

## 最终行为

1. 资格仍为萨莱因邪 DK + 瘟疫降临；仅选择脏腑之力天赋时额外监听两个括号事件。群怪仍自动按至少 3 个可观察、活着、可攻击、进战的非玩家姓名板判断，无手动开关。
2. 仅公开 81340 的“未显示 → 显示”建立一次可消耗记录。重复 SHOW 不推测刷新/层数；记录超过 10 秒或收到 HIDE 时失效。临近推算到期 0.15 秒不再认定可消耗。
3. 在该记录有效时收到玩家缠绕/传染（含替换）成功，推算脏腑之力到本次施法后 5 秒。GUID 去重；一次观察最多认一次消耗；普通缠绕不会续上力量。吞病周期结束不会捏造光环消失，环境重置则清除全部推断历史。
4. 原吞病时间 `base = 主窗口结束 - 2 GCD` 保留。单体已经观察到本轮收割时按收割截止，不再额外限制 DT；群怪忽略收割，在尚有效的心脏与 DT 中取较早截止。心脏过期而 DT 仍在，改回 DT。
5. 力量推算足以覆盖 `base`（及已发生 spender 的 GCD）时，不提示再次消耗括号。力量过早结束时，不为了它提前吞病。
6. 缺少力量覆盖、有可推断的括号、且原时间之前还够打一发 spender（1 GCD + 0.2 秒余量）时，才先提示消耗括号。准备最早出现在 `base - 3.8` 秒，给 5 秒力量留出 spender 带来的 1 秒突变延长及 0.2 秒余量。准备不后推 `base`；到了吞病优先级，不再为了力量补打一发。该提前准备策略不是 SimC 的原样 APL，也未经模拟对比证明提升。
7. 实际施法后重算突变续时、力量覆盖、当前 spender GCD 与单体/群怪分支；语音保持每轮最多一次。同一行在准备阶段显示“先打缠绕 → 吞病”或“先消耗括号 → 吞病”，数字仍是吞病剩余时间，其余时候保持“快打吞病”。默认语音与文字提前 3 秒，设置仍在暴雪面板，无斜杠命令。

## 回退与限制

- 事件无法注册、没有样本、ID 为秘密值：不依赖这条记录，使用基础吞病窗口。秘密括号不会取消整个突变周期；不能公开解析的玩家施法仍按原策略放弃本轮。
- HIDE 先于施法成功：不通过几毫秒关联猜消耗，宁可漏掉这次力量。括号消失本身不证明消耗；多层、无 HIDE 的刷新也不作精确推断。
- 无直接光环校正，因此过期、移除、加载时已存在光环、漏事件可能使推断与实际不同；不能声称获得真实 buff 时长。血DK的 12 秒版本未用于邪DK。
- 单体没观察到收割时沿用 DT 回退，区别于完整 APL 的收割前置条件；无法观察的其他饰品、疾病覆盖、目标血量、存活时间、实际 debuff 命中、未来操作不参与求解。
- 姓名板并非 SimC 的真实 active_enemies；不能观察的敌人会漏算，陌生战斗的敌人可能被计入。自动分支是当前信息下的近似。

## 性能与验证

没有新增轮询、光环扫描或战斗日志解析；两个事件按天赋启停。括号与力量只记录标量，沿用至多一个定时唤醒；仅文字可见时沿用 0.1 秒刷新。未进行游戏内 CPU 基准测试。

离线测试：Engine 83 项编号断言，另覆盖 448 个时间点的不提前/不延迟/不凭空生成力量约束；Runtime 65、Loader 15、Enemies 23 项编号断言。覆盖重复事件、过期、秘密值、注册失败回退、替换传染、DT 结束后的单体收割窗口、准备阶段截止、动态续时与语音只播一次。Lua 5.1 语法检查通过。

静态验证明细保存在 `validation-core-0.3.0.json`、`validation-loader-0.3.0.json`，摘要为 `validation-summary.json`。loadValid/staticValid 只代表列出的静态检查，不证明战斗秘密值、污染安全或实际游戏效果。
